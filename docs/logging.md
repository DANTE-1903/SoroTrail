# Log Schema

All structured log lines produced by SoroTrail use the `log/slog` JSON handler.
Every log line that corresponds to a unit of work carries a `request_id` field,
allowing operators to trace a single request end-to-end through the API, the
store, and the RPC layer, and any downstream systems.

The id is carried on the `context.Context` rather than passed as an argument,
so it reaches the store and RPC decorators through the same context the tracing
decorators already thread through those layers. The guarded store tags its
slow-query log lines with it, and the RPC retry/failover clients tag their
error lines with it.

Background work that has no originating HTTP request still writes the same
field: each worker logs a stable job id (`ingester`, `pruner`, `auditor`, or
`webhook`) so one field always identifies the work that produced a line.

## Standard Fields

| Field         | Type   | Description                                          |
|---------------|--------|------------------------------------------------------|
| `request_id`  | string | Correlation identifier. For HTTP requests it is echoed from the incoming
`X-Request-ID` header if present, otherwise generated by the server. The same
ID is set on the response header `X-Request-ID` so clients
can reference it in support requests. For background work it is the stable job
id (`ingester`, `pruner`, `auditor`, `webhook`). |
| `route`       | string | HTTP method and path, e.g. `GET /events`.            |
| `status`      | int    | HTTP response status code.                           |
| `duration_ms` | int64  | Request duration in milliseconds.                    |
| `error`       | string | Error message when the log line describes a failure. |

## Log Line Examples

### HTTP request summary (info level)

```json
{"time":"2026-07-25T12:00:00Z","level":"INFO","msg":"http request","request_id":"abc123","route":"GET /events","status":200,"duration_ms":15}
```

### Error log (error level)

```json
{"time":"2026-07-25T12:00:00Z","level":"ERROR","msg":"querying events","request_id":"abc123","route":"GET /events","error":"connection refused"}
```

### Slow store query (warn level)

Emitted by the guarded store when a query exceeds `API_SLOW_QUERY_THRESHOLD`.
The `request_id` is the originating HTTP request or background job.

```json
{"time":"2026-07-25T12:00:00Z","level":"WARN","msg":"slow store query","request_id":"abc123","query":"store.QueryEvents","duration":3012,"error":null}
```

### Background job line (info level)

A worker's lines carry its stable job id in the same field, so a single value
ties the job's own logs to the store and RPC activity it caused.

```json
{"time":"2026-07-25T12:00:00Z","level":"INFO","msg":"prune sweep complete","request_id":"pruner","deleted":1200,"through_ledger":900000}
```

## Field Conventions

- `request_id` is always a string, never numeric or empty.
- `route` uses `METHOD /path` format (e.g. `POST /subscriptions`).
- `duration_ms` is an integer (milliseconds), not a `time.Duration` string.
- `error` is only present on error-level log lines and contains the error message
  string.
- All other fields are context-specific (e.g. `id`, `count`, `through_ledger`).
